nubstack

Local network test guide

Shipped commands, permissions, and the chat output to expect on the Docker Velocity stack (hub, optional minigame, optional Fabric). Join localhost:25565 with vanilla Minecraft 26.2, or run the Mineflayer suite from the command line.

Setup Mineflayer suite aegis harbor gatekeep loom spotlight cull ledger amber tether cairn Velocity

Setup checklist

  1. ./scripts/use-java.sh ./gradlew build
  2. cp testbed/.env.example testbed/.env (optional overrides)
  3. ./testbed/scripts/sync-plugins.sh
  4. docker compose -f testbed/docker-compose.yml up -d
  5. Join localhost:25565 (plain vanilla spawn on hub).
  6. Optional backends: docker compose -f testbed/docker-compose.yml --profile minigame up -d (then /server minigame) and docker compose -f testbed/docker-compose.yml --profile fabric up -d (then /server cairn).
  7. ./testbed/scripts/seed-demo.sh [your-ign] ops the bots and your name on every running backend and sets starting ledger balances.

Permissions on Paper and on Velocity

Paper commands that default to op need /op on the backend you are standing on (./testbed/scripts/wait-and-op.sh your-ign does it for hub, minigame and fabric). Velocity has no op list, so /aegis, /gatekeep and /harbor admin need a permission plugin. The testbed installs LuckPerms on Velocity with JSON storage and three seeded bots:

BotGroupVelocity nodes
Bot1staffaegis.* subcommand nodes, gatekeep.admin, harbor.admin, harbor.priority.staff
Bot2defaultnone
Bot3vipharbor.priority.vip

Your own name is not seeded in git. ./testbed/scripts/seed-demo.sh your-ign writes a staff user file into the running Velocity container so your account can run the same commands. Without that, a Velocity command you may not use falls through to the backend and prints Incorrect argument for command or Unknown or incomplete command.

Honest status: Mineflayer joins as protocol 26.1 and ViaBackwards (and ViaFabric on Fabric) translate to 26.2, so a real 26.2 client is the better check for anything visual. Click-to-copy, hover text and the resource pack are not asserted by bots; they are covered by Java unit tests or a manual look. When the Tether Discord bot is configured in testbed/.env, its chat bridge forwards bot chat and joins to that Discord channel; blank the three TETHER_DISCORD_* variables for quiet runs.

Low memory hosts

Each Paper or Fabric container is capped at 1280 MiB. When the host swap is full, the kernel can kill a backend JVM at startup (Docker shows it restarting, dmesg shows a memory cgroup kill). Lower the heap with HUB_MEMORY=768M, MINIGAME_MEMORY=768M, FABRIC_MEMORY=768M in testbed/.env, or stop a backend you are not using.

Mineflayer suite CLI

Black-box bots join through the proxy with offline auth, run the shipped commands, and assert chat text, action bars, kicks and inventory. There is no web runner; use the command line from the host. 

cd testbed/bots
npm install
npm run smoke            # three bots join (join/spawn only)
npm run test:ledger      # one plugin
npm run test:all         # whole suite in order, stops at the first failure
npm run test:all -- --continue   # keep going and report every failure

Scenarios skip with a reason when a backend is not running. Environment variables: PROXY_HOST, PROXY_PORT, BOT_VERSION (default 26.1), BOT_SEND_GAP_MS (default 350, spacing between one bot's commands). Every run writes a JSON report to testbed/bots/reports/ (gitignored); a failure prints the bot's last 20 chat lines.

Helpers: ./testbed/scripts/gatekeep-profile.sh strict|default copies the strict overlay (plugin-config/velocity/gatekeep-strict/config.yml) into the running Velocity container; apply it with /gatekeep reload as staff.

Aliases (config toggled): /gban, /gmute, /gunban, /gwarn, /hist, /checkpunish. Each staff member has a punish cooldown of 1500 ms (Slow down (1s)); durations are 10m, 1h, 1d, 7d, 30d, perm.

Manual test plan

  1. Two clients (or a client and a bot). As staff: /aegis ban Bot2 5m testing.
  2. Confirm Bot2 is kicked and cannot reconnect; /aegis unban Bot2 and reconnect.
  3. /aegis mute Bot2 10m spam, chat as Bot2, expect the muted notice; /aegis unmute Bot2.

gatekeep Velocity

Login throttling by remote address, with a support code on the deny screen.

CommandPermissionExpected output
/gatekeep, /gatekeep helpgatekeep.adminClickable help.
/gatekeep statusgatekeep.adminTracking N addresses, N denied since start. Limit 30 per 1 minute. then the busiest addresses (172.23.0.1 . 1/30).
/gatekeep check <ip>gatekeep.adminAttempts, retry time and the support code (GK-...).
/gatekeep clear <ip>, clear *gatekeep.adminForget one address, or all with a confirm.
/gatekeep reloadgatekeep.adminReload config.yml without resetting counters.

The testbed raises max-attempts to 30 so bots are not refused. To see a real denial, copy the strict overlay (3 attempts per 60 seconds) with ./testbed/scripts/gatekeep-profile.sh strict, run /gatekeep reload, reconnect four times, then switch back with ./testbed/scripts/gatekeep-profile.sh default and reload. Bots all share one address, so keep a staff session open to run /gatekeep clear <ip>.
